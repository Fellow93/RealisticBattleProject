- ARMY COMPOSITION (2026-10-29, USER RULES: armies with no / token infantry, cavalry- or HA-heavy armies, enemies without infantry; HYBRID design rule: no hard categories — continuous ramps for tuning knobs, behavior weights for which job a formation takes, hysteresis/latches only for real either/or choices; every k logged; k = 0 = the old behaviour, so a normal mixed army is unchanged). `Behaviors/Custom/ArmyComposition.cs` (AI-thread safe, cached QuerySystem data; immutable `Snapshot` per Team rebuilt on read ≤ 1 / `RefreshSeconds` 1 s, shares / men in `Shares[8]` / `MenBy[8]` arrays (0..3 own, 4..7 enemy) behind the named getters, Team-keyed ConcurrentDictionaries; ONE tuning table at its top holds every number of these rules — ramps, bands, the merged shared thresholds `InMelee` 0.1 / `EngagedGap` 30 m / `WeakShrink` 0.6, and the k = 1 end of each blend (`CavalryLimitFactor`, `SpotCavalryPenalty`, `ActiveSortieGrowth`/`ActiveHomeLeash`, `OutshotSecondsNoFoot`/`BehindRangedGapNoFoot`, `WearDownLossFull`/`WearDownTimeFull`/`WearDownAmmoOpen`, `MountedArmyStart`/`MountedArmyShare`, `MainEnterStrengthShare`/`MainKeepStrengthShare`); shared rules written once: `IsDryAmmo` / `IsDry(f, out ammo)`, `NoMainRoles(team)` (the plan's NoMain: initiative), `EnemyOnOurFoot` (wear-down footEngaged, CavalryCommit's kWeak engaged); Move points of FollowCavalry / the wear-down guard / the HA push = `Behaviors/Custom/CachedMovePoint.cs` (copy + one SetVec2MT, rebuilt > 5 m after ≥ 2 s or forced)): USER RULES 2026-10-29: shares by MEN × class weight (`WeightInfantry`/`WeightArchers` 1, `WeightCavalry` 1.5, `WeightHorseArchers` 1.3), never FormationPower; CATEGORIES BY TROOP TYPE (`MenOf` = the formation's logical class counts, i.e. the troop's DefaultFormationClass via `Mission.GetAgentTroopClass`, array reads; skirmishers = archers, light cavalry = HA; `CategoryOf` = majority, mounted at ≥ 50 % mounted men; `IsMounted`/`IsHorseArchers`/`IsArchers`/`IsMeleeInfantryType`) — ammo never changes a category; "dry" is a STATE (`AmmoShare` = men with ammo ÷ archer+HA men, `IsDry` under `DryAmmoShare` 0.2, the one constant every dry rule uses); NOTE RBM's ManageFormationCounts prefix (FormationCounts.cs) still physically moves archers with ≤ 5 rounds into the Infantry formation (and dismounted riders too): that formation's category stays its majority, so dry archers never make it TeamMain while they outnumber the infantry, and the army shares are unchanged by the move. DISMOUNTED riders (`MenOf` → `Dismount`): mounted men = the cached physical mount share (QuerySystem `Cavalry`/`RangedCavalryUnitRatioReadOnly` over the four ReadOnly ratios, field reads, HasMount-based) × men, capped at the troop-type count; the rest move cavalry → infantry, HA → archers in proportion (categories too); COMPOSITION `dismounted=own/enemy`. TOKEN FORCE per category, own and enemy (`Snapshot.OwnToken`/`EnemyToken` bits, hysteresis carried in the snapshot): weighted share < `TokenEnterShare` 0.10 AND < `TokenEnterMen` 60 men, leaves at ≥ `TokenLeaveShare` 0.15 or ≥ `TokenLeaveMen` 80; a token category never drives a role or ramp (no main / anchor / archer stand / initiative / FollowCavalry "our cavalry" / wear-down hold, kWeak 0 when all our mounted are token, an enemy token category = absent in kFoot/kCav/kHA, `EnemyFootTokenOnly` for ArmyForward's enemy infantry and the HA push's "only mounted left", ProtectFlank never guards a token IsMainFormation). Smoothed by an EMA (`SmoothSeconds` 10 s) — own Infantry / Ranged (archers) / Cavalry / HorseArchers / Mounted, `HorseArcherOfMounted`, enemy EnemyMeleeFoot / EnemyRanged / EnemyMeleeCavalry / EnemyHorseArchers, `CavalryStrengthRatio` (own non-token mounted ÷ enemy non-token melee cavalry, cap 10), raw strength (weighted men)/men, `StartEnemyStrength` (first snapshot, + every later rise of the enemy's strength = arrivals); RESEED (no smoothing) when a side's men grow > `ReseedGrowth` 1.2 × their lowest since the last seed and once at the terrain publish (`RequestReseed`); `Limited` = ArmyScale NoPlans → every k 0; main-thread logs read only the published snapshot (`TryPeek` / `DescribePeek`; PLAN (one selection point): every composition decision lives in the snapshot, made once in its build (`BuildPlan`, ≤ 1 / s, every latch carried from the previous snapshot; readers accept ≤ 1 s lag): the k values (`KFoot(team)` etc. read them), `FootRangedEngage` band (on at kFoot 0.5, off 0.3), the ONE main-body verdict `InfantryLeads` (the TEAM's smoothed weighted infantry share `TeamInfantryShare` ≥ `MainEnterStrengthShare` 0.25, kept to `MainKeepStrengthShare` 0.15, never with own infantry a token force — USER RULE: infantry under it never leads and never holds the line), `Main` (= `FormationCohesion.TeamMainWith(team, verdict)`), `NoMain` (no main, not Limited), `FootAnchor` (no main only: the strongest AI foot formation of a non-token category with ≥ `FormationCohesion.MinMainMen` and ≥ `AnchorMinFootShare` 0.15 of the team's foot men, held until another has `SwitchRatio` 1.2 × power;
