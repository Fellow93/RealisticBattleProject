# RBMAI — battle AI: overview, layout, reset, robustness

Moved verbatim from CLAUDE.md on 2026-10-30. Keep adding design notes for this area here, not in CLAUDE.md.

**RBMAI** — Battle AI (the posture/stamina system, AI kick/bash and the combat slow motion moved out to RBMStance on 2026-10-13). Patcher entry: `RBMAiPatcher` (uses `Harmony.PatchAll()`, so file location is cosmetic — patches are discovered by attribute, not registered by hand). References RBMConfig and RBMStance (Frontline reads posture/stamina, the developer battle-stats overlay `AiModule/Diagnostics/BattleStatsLogic.cs` shows the kick/bash counters). As of 2026-07-18 the module was reorganized from a handful of multi-thousand-line monoliths into subsystem folders under `AiModule/`. Large classes were split across files using `partial class` (and, for `Utilities`, partial static files at project root) so no call sites changed. Namespace stays flat `RBMAI`; the old-style csproj lists every file with an explicit `<Compile Include>` — **update it when adding/moving files**. Layout:
- `AiModule/Behaviors/` — formation behavior patches (`SkirmishBehaviors`, `DefenseBehaviors`, `FlankBehaviors`, `AdvanceBehavior`, `AgentSpeedAndParams`, `MiscBehaviorPatches`); custom `RBMBehavior*` subclasses under `Behaviors/Custom/`.
- DECISION TRACE (2026-10-23, user: have the whole chain in our hands; step 1 = OBSERVATION ONLY, no behavior change): `AiModule/Diagnostics/DecisionTrace.cs`, on only while the AI behavior log is open (`DecisionTrace.Active`, set in `AiBehaviorLogic.AfterStart`, cleared at mission end / `MissionStartReset`; every hook returns on it first). Thread-static writer scope pushed in a prefix / restored in a finalizer around `FormationAI.TickOccasionally(float)` ("formAI:<active behavior>"), `TeamAIComponent.TickOccasionally` ("tactic:<tactic>"), `MakeDecision` ("decide:<tactic>", Priority.First so RBM's re-pick prefixes are inside), ChargeGuard's Tick re-apply ("chargeGuard"), ReactionMonitor's check ("react"); none = "player"/"other". Change-only records vs the last recorded value: move (hooked in RBM's existing SetMovementOrder prefix after the Charge conversion + ChargeGuard: kind, Move point > 5 m, ChargeToTarget target; ChargeGuard's rewrite = "<writer>>chargeGuard ... asked=K"), arr / width (`SetArrangementOrder` / `SetFormOrder` prefixes), facing SWEPT after each scope (`SetFacingOrder` is a JIT-inlined one-liner, never patch it), beh (FindBestBehavior switch), tactic (MakeDecision before/after). The BEHAVIOR queues (TerrainSpots/BattlePosition/ChokeHold/Hedgehog/Cavalry/Shape) and REACT lines add notes (`DecisionTrace.Note`). Per-formation state ConcurrentDictionary by reference under its own lock, records to a capped ConcurrentQueue, drained on the main thread (`AiBehaviorLogic.OnMissionTick` → `Drain`): AI log `DECISION` (≤ 1 per formation per 0.5 s, chain + notes) and `FLIP` (Move point reversing > 20 m jumps > 3×, or order kind / arrangement / behavior > 2×, in 30 s, with the writers) lines, documented in the AI log header; checker check 13. Not traced yet: behavior weights.
- `AiModule/Misc/MissionStartReset.cs` — the one place that clears every RBMAI static holding an `Agent`/`Formation` (plus native `Formation._simulationFormationTemp`), called from `RBM.SubModule.OnBeforeMissionBehaviorInitialize` (top of `Mission.AfterStart`, main thread, before any AI tick). **Add any new Agent/Formation-keyed static there.** Not a Harmony patch on purpose: RBMAI's `PatchAll` only runs from `RBMAIPatchLogic.EarlyStart`, inside `AfterStart`, and `FirstPatch` unpatches on every game start/load. (RBMStance's statics have their own `StanceReset`, called from the same hook.)
- ROBUSTNESS PASS (2026-10-23): native catches nothing on the async AI tick (Team.Tick → TeamAIComponent / Formation / FormationAI / tactics / behaviors), so any exception there was a crash. `AiModule/Misc/AiTickGuard.cs` puts swallowing finalizers on `TeamAIComponent.MakeDecision` / `.TickOccasionally` / `.Tick`, `FormationAI.TickOccasionally` and `Formation.Tick` (the rest of that team's / formation's tick is skipped, last orders stand; OutOfMemory passes); each distinct failure (site + exception + TargetSite) is counted and written at its 1st/10th/100th/1000th/every 10000th time (first with its stack) to the rgl log (Debug.Print) and the open AI log ("# [RBM AI] GUARD ..."), queued on any thread, written on the main thread by `AiTickGuard.Flush` (`RBMAIPatchLogic.OnMissionTick`), totals of the last mission at `AiTickGuard.Clear` (top of MissionStartReset). New catches should call `AiTickGuard.Report`, never swallow silently. `RBMAiPatcher.DoPatching` patches class by class (Harmony's PatchAll loop: `HasHarmonyAttribute` + `CreateClassProcessor(type).Patch()`), a failing class is reported and skipped instead of aborting the rest and throwing out of EarlyStart. MissionStartReset runs `TacticSelection` / `TerrainFlankPlan` / `ReactionMonitor` / `FormationMarkerPatches` clears through `Guarded` (by-name FieldRefAccess in static initializers → TypeInitializationException after a game update, in every mission even with RBM AI off), and SubModule wraps the whole reset; `TacticSelection.CurrentTacticRef` is now a null-safe method over a try-built FieldRef (also `AvailableTacticsRef`, `TerrainFlankPlan.IsTacticReapplyNeededRef`). ChargeGuard's per-formation State is locked (written by the AI thread and by the player's main-thread orders; `PlayerOrder`/`ReleasedOrder` are multi-WorldPosition structs). Also cleared per mission now: FormationMarkers' static smoothing cache + Mission, and the AGENTS counters `pfxCalls`/`pfxSet`/`devCaps`. Known, left alone: Frontline's `[ThreadStatic]` scratch agent lists keep the last field battle's agents per worker thread until the next one (bounded, load-bearing code). PERF (gameplay-neutral, same picks/orders/log text): `NearestAgentFromMultipleFormations` skips a formation whose snapshot bounds are ≥ the best distance + 0.01 m (no man in it could win, same order/ties); `FormationFightingInMelee` (key formation+ratio) and `HoldLateCharge.MeleeShare` cache one answer per exact `MBCommon.GetTotalMissionTime()` value + unit count (`fightingInMeleeCache` / `ClearMeleeShareCache`, MissionStartReset); TerrainSpots `KeepFailure` asks the melee test only when a mounted enemy would be nearest; significance helpers in `Utilities.Formations.cs` use plain loops (`CountFormationsWithUnits`/`AddFormationsWithUnits`) instead of LINQ; reason strings only built where read: `OrderExemption`/`ArmyAdvancing` constants, ChargeGuard `go` words + `GoText` on the log line, ranged labels table, `explain` flags on TerrainSpots `TakeFailure` / ArcherCover `Validate` / SupportFire `EnemyFail`, SupportFire's "none" dedupe text only with the log on. Not done: retry throttles for failed ArcherCover/SupportFire searches and ClampGuard caching (would change timing); reusing the unit-snapshot buffers (snapshots are shared and read by other threads after publish) and `ApplyActionOnEachUnit` for the melee walks (live-list foreach, unsafe off the main thread).
- `AiModule/Agents/` — `partial class AgentAi` patches (`AgentStats`, `CombatFixes`, `Weather`, `TickPatches`). `AgentStats`' `SetAiRelatedProperties` postfix (Priority.Low) sets the AI block/parry/aim values; picks the posture-tuned block/parry set under `rbmStanceEnabled && postureEnabled`. Stamina's multipliers on top are RBMStance's `StanceStatsPatch`.
- `AiModule/Voices/FormationShoutsLogic.cs` — formation shouts (MissionLogic, added in `RBM/SubModule.cs` under `rbmAiEnabled` when `formationShoutsEnabled` or `orderReactionDelayEnabled` is on; each feature re-checks its own toggle). Soldiers echo/answer player orders (`Team.OnOrderIssued`), AI captains call movement-group/arrangement changes, plus halt/formed grunts, charge yells, a contact roar (`OnMeleeHit`), melee chatter and per-culture infantry march cadences (`Cadences`, keyed by culture StringId), horns (module sounds `rbm/horn/charge|order/<culture>`: mounted formations' charge horn leads the yells, Aserai/Nord order horn; own longer carry distances `Horn*`), all through one voice queue with per-agent cooldown and a global per-second cap. `orderReactionDelayEnabled` (experimental) re-sets each man's engine decide time from the `OnOrderIssued` handler, which fires right after vanilla's `AfterSetOrder` default. That only delays Charge → Move; Move → Move is delayed by `AiModule/Orders/OrderReactionHold.cs` (a Priority.Last postfix on `HumanAIComponent.GetFormationFrame`, worker + serial threads, managed reads only) which returns each man's OLD frame until his release time, stamped by a prefix on `OrderController.AfterSetOrder`; charges are never held. AI orders are stamped by prefixes on `Formation.SetMovementOrder`/`SetArrangementOrder` (AI-controlled formations, real group/arrangement change only; these run on the async AI thread, so a thread-static `System.Random`, never MBRandom). Its Agent-keyed static is cleared in `MissionStartReset`. ⚠️ Main thread only: AI order changes are POLLED in `OnMissionTick`, never via `Formation.OnBeforeMovementOrderApplied`/`OnAfterArrangementOrderApplied` (those fire on the async AI thread); all state is instance fields cleared at mission end.
- `AiModule/Frontline/` — the Frontline system (everything from the old `Frontline.cs`): `FrontlineDecision.cs` (the `partial class Frontline` decision AI), `FrontlinePositioning.cs` (`Frontline.OverrideFormation`; reads posture/stamina from RBMStance's `AgentStances` on the worker thread, gated `rbmStanceEnabled && postureEnabled`), `FormationMovement.cs` (HumanAIComponent movement gates), `AgentPanicFix.cs`. ⚠️ Load-bearing worker-thread crash-safety code — move verbatim, never restructure the gates. Static obstacles (2026-10-20): every step branch first runs `IsStepBlocked` (press-release cooldown, deep-water line via `DeepWaterSteering.CrossesDeepWater`, navmesh reachability of a 0.6 m probe via `Mission.IsFormationUnitPositionAvailableMT` — the one spatial query native itself makes from this job, read-locked; memoised per agent ≤ ~3/s) and, before pinning, `IsPressingAgainstObstacle` (< 0.15 m progress in 2 s → release + 2.5 s cooldown; positions only); blocked = hold for BackStep/FindAlly/Flank (2026-10-22: native frame under a charge = back ranks pushing), native frame (`return true`) for the Attack step; counters `flUnreach/flDeep/flProbes/flPress` on the AI log's AGENTS line.- `AiModule/Formations/` — general formation-grid safety patches: `FormationGridGuards.cs` (`OverrideLineFormation`, from the old `Behaviours.cs`). ⚠️ Also load-bearing worker-thread crash-safety — move verbatim.
- `Utilities/` (project root) — `public static partial class Utilities` split into `Utilities.Formations.cs` / `.Targeting.cs` / `.Geometry.cs` / `.Combat.cs`.
