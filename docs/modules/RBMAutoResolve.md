# RBMAutoResolve — detailed auto resolve

Moved verbatim from CLAUDE.md on 2026-10-30. Keep adding design notes for this area here, not in CLAUDE.md.

**RBMAutoResolve** — the Detailed Auto Resolve (equipment-aware campaign battle simulation), split out of RBMCampaign on 2026-10-13 so it works with RBM Campaign off. Gated ONLY on its own setting `simulationEquipmentEnabled` (default on; `SimulationEquipmentPower.SimulationEnabled` also needs `simulationEquipmentPowerWeight > 0`), never on `rbmCampaignEnabled`: own Harmony instance `com.rbmautoresolve`, patched by `RBMAutoResolvePatcher.DoPatching` (`PatchAll`; War Sails patches skip themselves via `Prepare`) from `SubModule.ApplyHarmonyPatches`, and `RBMSimulationCampaignBehavior` registered for every campaign while it is on (ahead of RBMCampaign's behaviors). Its config keys stay under `/Config/RBMCampaign/Simulation*` (no migration). References RBMConfig only; namespace flat `RBMAutoResolve`; explicit `<Compile Include>` csproj — **update it on add/move**. Layout: `Simulation/` (all the sim patches + helpers + `RBMSimulationCampaignBehavior`, which resets the sim caches per session and flushes its own log hourly/before save; `SimulationSidePower` = a side's map strength via `PartyBase.CalculateCurrentStrength` + the naval landing discount, the one copy RBMCampaign's `StrategicTroopPower.SidePower`/`LandingFactor` forward to), `UI/SimulationPanel/` (the live panel on the map battle-simulation view; prefab `RBMXML/GUI/Prefabs/SimulationBattlePanel.xml`), `Diagnostics/SimulationLog.cs` (`logs/simulation/`, gated by `simulationLoggingEnabled` alone). Troop perks (RBM's hero perks for regular troops) count in the auto-resolve through `Simulation/SimulationTroopPerks.cs`, the only RBMAutoResolve file that reads `RBMConfig.TroopPerks`. It reads the map directly; never widen `TroopPerks.AppliesInMission` (campaign-map models must not see troop perks). Gate: `simulationPerkSystem` + `rbmCombatEnabled` + `troopPerksEnabled`. The same file also prices heroes' own personal perks (under `simulationPerkSystem` alone; not their HP/Veterinary, which native already pays). They ride in the kit-cache key as a bit (the baselines stay perk-free), and hit points go into `CommandedHealth`, so strategic power gets HP only (AUTO_RESOLVE.md §7a). Siege-engine wounds and the absolute blow cap are priced against `SimulationTroopHitPoints.ReferenceWoundPoolFor` (125 trooper / 100 hero), never the man's own pool, so HP perks protect. Design doc: `RBMAutoResolve/AUTO_RESOLVE.md`. RBMCampaign uses it (strategic troop power with its log and tooltip, upgrade formation weighting) by referencing it; members it needs are `public`. ⚠️ RBMCampaign's `RBMCampaignSessionBehavior` also calls `RBMSimulationCampaignBehavior.ResetForNewSession()`, because strategic troop power reads the sim's kit/HP/perk caches even with the auto-resolve off.
