# RBMCombat — combat mechanics

Moved verbatim from CLAUDE.md on 2026-10-30. Keep adding design notes for this area here, not in CLAUDE.md.

**RBMCombat** — Combat mechanics overhaul. Patcher entry: `RBMCombatPatcher.DoPatching` (`PatchAll`). References RBMConfig and RBMStance (posture/stamina effects on damage in `DamageRework.Core.cs`, gated `rbmStanceEnabled && postureEnabled`; the training field's posture reset; the kick/bash damage branch is gated `rbmStanceEnabled && aiKickBashEnabled`). As of 2026-07-19 the module was reorganized from a handful of multi-thousand-line monoliths (DamageRework/ArmorRework/MagnitudeChanges/RangedRework/CampaignChanges + a 1577-line Utilities) into subsystem folders under `CombatModule/`. Each monolith was split with `partial class` (and `partial static class` for `Utilities`) so no call sites changed; namespace stays flat `RBMCombat`; `PatchAll` finds patches by attribute so file location is cosmetic. The old-style csproj lists every file with an explicit `<Compile Include>` — **update it when adding/moving files**. Layout under `CombatModule/`:
- `Damage/` — `partial class DamageRework` split into `.Core.cs` (the `ComputeBlowDamage` rewrite + nested shield helper/patch), `.Blows.cs`, `.HitReaction.cs`, `.Entities.cs`. ⚠️ two DISTINCT `GetAttackCollisionResultsPatch` classes coexist (a nested-private one in `.Entities.cs` and a separate top-level one in the same file) — the name only disambiguates by nesting, keep them in separate scopes.
- `Armor/` — `partial class ArmorRework` split into `.Human.cs` / `.Horse.cs` / `.Dispatch.cs` (the public `GetBaseArmorEffectivenessForBodyPartRBM` / `GetArmorMaterialForBodyPartRBM` dispatchers DamageRework calls); `ItemModifierPatches.cs` holds the two top-level `ModifyArmor`/`ModifyModifyDamage` patches.
- `Magnitude/` — `partial class MagnitudeChanges` (static): `.Core.cs` (shared fields), `.Melee.cs`, `.Thrust.cs`, `.Missile.cs`, and `Tooltips/` (`.WeaponTooltip.cs` / `.ArmorTooltip.cs` / `.StatCalcs.cs`).
- `Ranged/` — `partial class RangedRework`: `.State.cs` (shared dictionaries + reflection cache), `.EquipWield.cs`, `.MissileSpeed.cs`, `.Reload.cs`, `.Siege.cs`, `.Collision.cs`; plus `RangedWeaponStats.cs` (was `RangedAmmoCombo.cs`) and `RealisticWeaponCollision.cs`. `.StuckMissiles.cs` holds `RangedRework.StuckMissileLogic` (a `MissionLogic` added in `RBM/SubModule.cs` under `rbmCombatEnabled`): missiles the `.Collision.cs` stick branch attaches are registered with it and later fall out as loose pickable items (thrown weapons from shields and bodies, arrows/bolts from shields on a timer with a per-shield cap, arrows/bolts in bodies by a per-body cap only; `stuckThrownFallOutSeconds` / `stuckArrowFallOutSeconds`, 0 = vanilla). The loose item is a fresh copy spawned at the stuck one's frame, read after `ForceUpdateBoneFrames` (without it the frame lags the animation). The engine's missile entity and a weapon item lay the same mesh along different local axes (copy came out 90° sideways), so the copy is placed by its mesh (`EntityFrameForMeshAt`: entity frame × meta-mesh frame × mesh local frame matched between the two). Verified in game 2026-10-01. A bounding-box alignment was tried first and put the copy on the ground pointing up — an entity's local box is not usable for this. Reusing the stuck entity does NOT work: it stays skeleton-driven and floats along with the bearer, and there is no engine call to unhook an entity from a bone. ⚠️ The shield detach removes the missile's child entity behind the engine's back (no engine call exists) — it is isolated in `DetachFromShield` so it can be swapped for a re-equip if it proves unsafe. NOTE: `OverrideSetAiRelatedProperties` (reload) was promoted out of the siege patch into `.Reload.cs`.
- `Horse/` — `partial class HorseChanges`: `.MountStats.cs` / `.MountedCombat.cs`.
- `Campaign/` — `partial class CampaignChanges`: `.Survival.cs` / `.Xp.cs` / `.TrainingField.cs` / `.TroopPower.cs` / `.Spawn.cs`. `OverrideDefaultMilitaryPowerModel` (in `.TroopPower.cs`) keeps only its two XP-power helpers; the morale/spawn/equipment patches were promoted into `.Spawn.cs`.
- `Items/` — `partial class ItemValuesTiers`: `.Pricing.cs` / `.Tiers.cs`.
- `Diagnostics/` — `BattleHitLog.cs` (sink) + `BattleHitLogic.cs` (producer `MissionLogic`).
- `TroopPerks/` — hero perks for regular troops (data loader: `RBMConfig/Shared/TroopPerks.cs`, file `RBMXML/rbm_troop_perks.xml`, loaded from `RBM.SubModule.OnGameInitializationFinished`). `TroopPerkEffects.cs` postfixes `CharacterObject.GetPerkValue(PerkObject)` during missions (v1.5.6 removed the `BattleEnvironment`/`out effectValue` overload; callers now pair the plain one with `PerkHelper.TryGetPerkEffectBonus`); `TroopPerkDisplay.cs` adds the "Perks" block to the troop tooltip (High priority, so it lands before RBMCampaign's appended recruit cost) and perk icons to the encyclopedia unit page. Gated on `rbmCombatEnabled` + `troopPerksEnabled`. `TroopPerkLog.cs` (thread-safe recorder fed by the postfixes; stack walk only on a key's first hit) + `TroopPerkLogLogic.cs` (MissionLogic, added under `troopPerkLoggingEnabled`, Debug & Logging) write one file per mission to `logs/troopperks`: each listed perk of each spawned troop as GRANTED / QUERIED-NOT-APPLICABLE / NEVER QUERIED, with callers. `tools/TroopPerkEditor/test-all-perks.xml` gives every personal perk to seven role-covering troops for that test. Edit the XML with the local page in `tools/TroopPerkEditor/` (run its `Build-TroopPerkData.ps1` first; keep its `NoTroopEffectPerkIds` parse working if you change that set in `TroopPerks.cs`). Which perks actually work for a troop under RBM (per-perk verdicts, the do-nothing set, Mighty Blow (loader skips it for troops with Athletics ≤ 250, as its HP bonus would be negative), RBM/vanilla issues found) is in `tools/TroopPerkEditor/audit/README.md`.
- `UI/PlayerArmorStatus/` — `PlayerArmorStatus.cs` (the `MissionLogic`, renamed from `PlayerArmorStatusLogic.cs`) + `PlayerArmorStatusVM.cs`.
- `RBMCombatPatcher.cs` — bootstrap, at `CombatModule/` root.
- `Utilities/` (project root) — `public static partial class Utilities` split into `.Collision.cs` / `.Physics.cs` / `.Skill.cs` / `.Ranged.cs` / `.ArmorDurability.cs` / `.Damage.cs` / `.VisualStats.cs` / `.WeaponProps.cs` / `.Config.cs` (root `Utilities.cs` holds the shared tuning fields).
