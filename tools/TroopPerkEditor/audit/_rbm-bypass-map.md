# RBM bypass map: where RBM replaces vanilla code that contains perk checks

Purpose: per-perk auditors look up "is the vanilla method that contains this perk check still executed under
RBM?". A troop perk (RBMConfig.TroopPerks, `rbm_troop_perks.xml`) only works if (a) the perk is checked through
`CharacterObject.GetPerkValue` (both overloads are postfixed in
`RealisticBattleCombatModule/CombatModule/TroopPerks/TroopPerkEffects.cs:33` and `:49`) and (b) that check still
runs. This file covers (b). Verified against the v1.5.4 sources in `decompiled/` and the RBM working tree on
2026-10-06 (branch `patreon-1.5.x`).

## Module gates (how a patch gets applied at all)

| Gate | Harmony id | When patched | Source |
|---|---|---|---|
| `rbmCombatEnabled` | `com.rbmcombat` | `RBMCombatPatcher.DoPatching` -> `PatchAll()`, from `SubModule.ApplyHarmonyPatches` (RegisterSubModuleTypes, OnGameStart, OnBeforeInitialModuleScreenSetAsRoot) | `RBM/SubModule.cs:57`, `RealisticBattleCombatModule/CombatModule/RBMCombatPatcher.cs:9` |
| `rbmAiEnabled` | `com.rbmai` | Only `MissionCombatantsLogic.EarlyStart` postfix at game start (`RBMAiPatcher.FirstPatch`); the full `PatchAll()` runs per mission from `RBMAIPatchLogic.EarlyStart` (a MissionLogic added only when `rbmAiEnabled`). So RBMAI patches exist only inside missions. | `RBM/SubModule.cs:49`, `:307`, `:414`; `RealisticBattleAiModule/RBMAIPatcher.cs:11-31` |
| `rbmCampaignEnabled` | `com.rbmcampaign` | `RBMCampaignPatcher.DoPatching` (campaign layer only, nothing in the mission damage/stat pipeline except party morale) | `RBM/SubModule.cs:65` |
| always | `com.rbmmain` | `RBM` project: XML merging, custom-battle UI, crafting; nothing battle-relevant | `RBM/SubModule.cs:40` |

The troop-perk postfix itself is in RBMCombat, so troop perks need `rbmCombatEnabled` (+ `troopPerksEnabled`)
no matter what (`RBMConfig/Shared/TroopPerks.cs:60-63`), and only fire while `Mission.Current != null` for a
non-hero in a Campaign (`TroopPerks.AppliesInMission`, `:108-116`; the map is only loaded for Campaign games,
`RBM/SubModule.cs:381-388`).

Whole-model replacement: **none in the battle pipeline.** The only `AddModel` is `RBMCampaign.RBMWorkshopModel`
(`RBM/SubModule.cs:229`, campaign workshops). Every agent-stat / apply-damage / strike-magnitude / morale / combat-XP
model is vanilla. NavalDLC's `NavalAgentStatCalculateModel`, `NavalAgentApplyDamageModel`, `NavalStrikeMagnitudeModel`
wrap the Sandbox models through `BaseModel`, so RBM's patches on `SandboxAgentStatCalculateModel` etc. still fire in
naval battles (Naval's own perk additions run after the base call and are not touched by RBM).

## Notes for auditors

1. **Only `CharacterObject.GetPerkValue` is granted.** Anything that asks a `Hero` directly
   (`Hero.GetPerkValue`, `characterObject.HeroObject.GetPerkValue`, `MobileParty.HasPerk`, `PerkHelper.AddPerkBonusForParty`,
   `AddPerkBonusForTown`, the ClanLeader branch of `AddPerkBonusForCharacter`) never sees a troop perk. Examples:
   `SandboxBattleMoraleModel.CanPanicDueToMorale` (party LeaderHero, Leadership.LoyaltyAndHonor),
   `DefaultCombatXpModel` party perks, RBM's Impale fallback (`RangedRework.Collision.cs:303`).
2. **`PerkHelper.AddPerkBonusForCharacter` only pays the Personal slot** (`decompiled/TaleWorlds.CampaignSystem/Helpers/PerkHelper.cs:73-91`):
   `isPrimaryBonus: true` needs `PrimaryRole == Personal`, `false` needs `SecondaryRole == Personal`. A call that asks
   for a Captain/PartyLeader slot does nothing for a troop. Watch for `isPrimaryBonus: false` calls
   (e.g. Engineering.Scaffolds in vanilla `InitializeMissionEquipment` and in RBM posture, Medicine.SelfMedication).
3. **Captain paths need the troop to be the captain.** `AddPerkBonusFromCaptain` / `characterObject2 = Formation.Captain`
   use the captain's CharacterObject, normally a hero. In normal play a troop is never a captain, so the captain half
   of a troop perk never fires. Vanilla also nulls the captain when the agent is its own captain.
4. **`agent.IsHero` / `IsHero` branches in vanilla** (troop perk cannot work there): `SandboxAgentStatCalculateModel.InitializeAgentStats`
   agent flags (Bow.HorseMaster, Crossbow.MountedCrossbowman, TwoHanded.ProjectileDeflection);
   `SandboxStrikeMagnitudeModel.CalculateStrikeMagnitudeForMissile` (Throwing.RunningThrow);
   `NavalMissionSiegeEngineCalculationModel.CalculateDamage` (Boatswain.ShipwrightsInsight); `DefaultCombatXpModel.GetXpFromHit`
   InspiringLeader (captain.IsHero). These matched the loader's old `HeroOnlyPerkIds`; after the audit that set became
   `TroopPerks.NoTroopEffectPerkIds` (`RBMConfig/Shared/TroopPerks.cs`), which lists every perk with a do-nothing verdict.
   `GetEffectiveMaxHealth` returns `MaxHitPoints()` for heroes; for troops it is `BaseHealthLimit` + party perks, and the
   troop's personal HP perks reach it through `DefaultCharacterStatsModel.MaxHitpoints` (BattleEnvironment.Any) only if
   `MaxHitPoints()` is evaluated while `Mission.Current` is set.
5. **BattleEnvironment overload.** v1.5 callers use `GetPerkValue(perk, env, isPrimaryEffect, out effectValue)` and some use
   `effectValue` as the magnitude (Athletics.IgnorePain primary in `SetPerkAndBannerEffectsOnAgent`, Crossbow.Piercer threshold,
   Crossbow.Pavise chance, Riding.DauntlessSteed/IgnorePain/Metallurgy captain checks). RBM's postfix returns false when
   `!perk.ApplicableInEnvironment(env, isPrimaryEffect)` (land vs sea) and otherwise fills `effectValue` from the matching
   bonus. Old one-argument calls (`GetPerkValue(perk)`, e.g. Riding.Sagittarius, Bow.MountedArchery, Throwing.MountedSkirmisher,
   Throwing.Impale, Crossbow.HammerBolts, Throwing.KnockOff, Athletics.StrongLegs on kicks) have no environment filter of their own.
6. **Epic perks** (`AddEpicPerkBonusForCharacter`) use the troop's raw `GetSkillValue` against `Min/MaxSkillRequiredForEpicPerkBonus`;
   low-skill troops get nothing even when the perk is granted.
7. **Stat pipeline order** (`SandboxAgentStatCalculateModel.UpdateHumanStats`, `decompiled/SandBox/SandBox.GameComponents/SandboxAgentStatCalculateModel.cs:632-838`):
   SetWeaponSkillEffectsOnAgent (RBMAI-replaced, #7) -> SetMountedPenaltiesOnAgent -> **SetPerkAndBannerEffectsOnAgent (all
   personal/captain stat perks; NOT patched)** -> SetAiRelatedProperties (RBMCombat postfix #8, then RBMAI postfix #9) -> weather
   AiShooterError -> RBMCombat UpdateHumanStats postfix (#10) -> NavalAgentStatCalculateModel naval perks (after base). A stat perk
   is lost only if its output field is reassigned after SetPerkAndBannerEffectsOnAgent: `ReloadSpeed` (re-implemented),
   `MissileSpeedMultiplier` (re-implemented), `WeaponRotationalAccuracyPenaltyInRadians` when mounted (lost),
   `ReloadMovementPenaltyFactor` for non-ranged infantry (moot), `AttributeShieldMissileCollisionBodySizeAdder` (lost),
   `CrouchedSpeedMultiplier` (re-implemented in #7). All other RBM stat edits are `*=` and keep the perk.
8. **Damage pipeline perks are intact.** `Mission.GetAttackCollisionResults` (`decompiled/.../Mission.cs:6534-6576`) still calls
   `AgentApplyDamageModel.CalculateDamage` on RBM's InflictedDamage, so every perk in `IsDamageIgnored`,
   `ApplyDamageAmplifications`, `ApplyDamageScaling`, `ApplyDamageReductions`, `ApplyGeneralDamageModifiers` applies (including
   shield-block reductions SteelCoreShields/ShieldWall, since a block's InflictedDamage is the shield damage). Armor-penetration
   perks in `CalculateAdjustedArmorForBlow` are kept (#1). Strike-magnitude perks are re-implemented (#3, #4). Knockback/knockdown/
   shrug-off/stagger/crush-through model calls are not patched, except the couch/brace dismount shortcut (#5).
9. **Effective skill carries captain skill perks into RBM's own math.** RBM's damage, magnitude, reload, sling and throw formulas
   call `AgentStatCalculateModel.GetEffectiveSkill` (unpatched), so captain perks such as OneHanded.WrappedHandles,
   TwoHanded.StrongGrip, Polearm.CleanThrust/CounterWeight, Bow.DeadAim, Throwing.StrongArms/RunningThrow (capt),
   Crossbow.DonkeysSwiftness, Throwing.FlexibleFighter, Riding.NimbleSteed, Polearm.Phalanx (party) still matter under RBM.
10. **RBMAI patches are per mission.** They are unpatched on every game start/load and re-applied at
    `RBMAIPatchLogic.EarlyStart`; with `rbmAiEnabled` off, rows #7, #9, #17 and the posture perk factors do not exist (vanilla
    behaviour for those). Stats are computed at spawn and on wield change, so a troop-perk toggle mid-mission shows only after
    the next `UpdateAgentStats`; the posture block-perk factors are cached in the agent's Stance.
11. **Misplaced priority attribute (harmless):** in `RangedRework.Reload.cs:29` `[HarmonyPriority(Priority.High)]` sits on
    `GetReloadPerkFactor`, not on `Postfix`. The postfix runs at default priority (400), still before RBMAI's `Priority.Low`
    postfix, so ordering is as intended.
12. **Inlining caveat** (from `TroopPerkEffects.cs:22-29`): if a listed perk silently fails for a troop in game while the
    vanilla path is shown here as executed, suspect JIT inlining of `CharacterObject.GetPerkValue(PerkObject)` into that caller.
13. **Out of scope by construction:** custom battle (map cleared, `RBM/SubModule.cs:385-388`), auto-resolve and campaign-map
    models (no `Mission.Current`), tournaments' simulated fights.
